# 冰淇淋冷柜温度与批次换货系统

门店冷柜的**温度监控 + 批次库存 + 临期换货 + 供应商回收**一体化管理。
纯 Python 标准库实现(零第三方依赖):SQLite 持久化、`http.server` Web 界面、
本地设备适配器模拟温度探头上报、进程内任务引擎周期扫描临期。

## 一条命令启动

```bash
python3 main.py            # 建库 + 写入温控/临期/回收样例 + 启动 Web(http://127.0.0.1:8000)
python3 main.py --reset    # 重建演示库
python3 main.py --no-serve # 只生成样例数据
python3 main.py --port 8080
```

## 六个业务视图

| 视图 | 内容 |
|---|---|
| 冷柜总览 | 各柜最新温度(合格/超限/断电离线)、货道占用、在柜件数、挂起任务 |
| 货道库存 | 冷柜**货道矩阵**格内显示商品规格、批次号、余量/容量、到期日与临期分层;混放红框、锁定加锁标 |
| 温度曲线 | SVG 折线,**绿色色带直接标出合格区间**(-22~-18℃);超限点草莓红实点、迟到补传点空心环 |
| 临期队列 | 按剩余天数分四层:已过期 / ≤3天 / ≤7天 / ≤14天,显示批次、位置、数量 |
| 换货单 | 突出**批次、数量、店员/配送员双向签收状态**;页面可直接配送员签收或拒收(数量回柜) |
| 回收对账 | 应收/实收/差异、结清/部分到货/数量不符;可登记补交,差异自动开任务 |

配色:香草白 `#FBF7EE` 底、海军蓝 `#16285B` 主色、草莓红 `#E23A4E` 告警。

## 六类任务

温度超限 `temp_breach`、冷柜断电 `outage`、批次混放 `mixed_batch`、
临期未换 `expiry`、包装破损 `package_damage`、回收数量不符 `recycle_mismatch`。
同 kind+单据去重,整改后自动关闭;临期任务由进程内 `TaskEngine` 每 60 秒重扫。

## 关键业务规则

- **批次不变量**:`收货 = 售 + 损 + 换出 + 在柜剩余`,且 `回收 ≤ 换出`;
  已报损/已换出数量永远不能回流可售库存。
- **换货**只能针对在柜、未锁定、余量充足批次;创建即店员确认并划出库存,
  必须由**不同的配送员**二次签收才算完成,随后自动开出回收单。
- **温度**:`(设备, 时间戳)` 主键保证读数幂等;早于已入账最新读数记 `late`;
  迟到读数只补曲线,**不新建事件、不覆盖已处置状态**;处置后事件冻结。
- **断电**:设备离线停止上报,恢复后继续;供电状态只由显式动作改变。
- **补货**:`BEGIN IMMEDIATE` 行锁 + 全局幂等键,并发两单恰好成功一次。
- **门店隔离**:所有单据写操作强制 `store_id` 过滤,跨店访问直接拒绝。
- **批次混放**:正常入柜拒绝向有余量的货道塞入新批次;整改期间暂停售卖。

## 演示数据(3 店 / 4 供应商 / 6 商品 / 4 冷柜)

- 上海 A 柜:超温事件已处置后,设备补传迟到超限读数(曲线可见,任务不重开);
- 北京 A 柜:跳闸断电,`outage` 任务挂起,实时上报停止;
- 上海 B 柜 A3 货道:两批次混放红框;另有双向签收完成 / 待配送员 / 拒收流程;
- 回收:8=8 结清、6 实 4 数量不符、4 实 2 部分到货;
- 临期四档:过期 / +2天 / +6天 / +12天(启动当天计算)。

## 代码结构

```

app/domain.py    全部业务规则与状态机(守恒/锁定/双向确认/隔离)
app/device.py    本地设备适配器:随机游走、断电离线、补传/注入读数
app/tasks.py     六类任务与临期分层、进程内周期扫描
app/seed.py      演示数据与六类任务样例
app/web.py       六个视图 + SVG 温度曲线 + 表单动作
tests/           单元/并发/隔离测试
```
